## Executive conclusion

The fastest path is not to chase every new SharpEmu commit as the main
project base. Keep `ps5recomp` as the stable native relinker/runtime, and use
emulators/toolchains as evidence sources behind importers and replay tools.

The best immediate source outside SharpEmu is `KytyPS5`. It is a real PS5
emulator codebase with current GPU work, AGC helpers, PM4 command handling,
runtime linker fallback logic, and 1507 unique `LIB_FUNC` NID registrations.
For the current Astro Bot package it overlaps 773 unique imports, including
256 imports that `ps5recomp` currently marks as missing. That is the first
automation target.

The second important group is PS5 ELF/NID tooling: `ps5-payload-dev/sdk`,
`flatz/ida_ps5_elf_plugin`, and `SharpProspero`. These should feed name,
library, ABI, SCE dynamic-tag, and loader validation data. GPLv3 or unlicensed
sources must be treated as reference data unless the whole combined project
intentionally accepts the license impact.

For graphics, keep SharpEmu as the known working short-term bridge, but use
KytyPS5 and shadPS4 to design the independent path:

`AGC/PM4 -> backend-neutral PS5 GPU IR -> D3D12 default + Vulkan secondary`.

## Concrete integration priorities

1. Add a KytyPS5 HLE source importer.

   Parse `LIB_FUNC("nid", handler)` from `C:\dev\reference\KytyPS5\src\libs`
   and emit source/evidence rows into `HleExternalCatalogLoader`. This converts
   the 256 Kyty-backed missing Astro Bot imports from blind missing NIDs into
   named candidate work items.

2. Add a generated `kyty-hle-overlap` report to the normal build.

   The CSV already generated by this audit should become a reproducible CLI
   report next to `imports-usage.csv`. Required columns:
   `nid,name,library,status,kyty_handler,kyty_file,kyty_line,called,blocking`.

3. Add SharpProspero catalog ingestion as names-only evidence.

   Use it to fill name/library gaps, especially AGC. Keep it low-confidence
   until each name is re-hashed through the PS5 NID algorithm and matched to
   the package import.

4. Harden SCE ELF/SELF metadata validation.

   Use the dynamic tag map and NID formula from `ida_ps5_elf_plugin` as a
   reference, then independently implement tests in `ps5recomp`:
   module info, needed modules, import/export libraries, hash/symbol table
   sizes, and PPR variants.

5. Move GPU work from "single blocker at a time" to data-driven replay.

   Extract PM4/AGC command buffers from the native runtime into replay files.
   Build `ps5gpu-replay` so shader/command bugs can be fixed without full
   relink and 45-second game probes. Use KytyPS5 and SharpEmu as differential
   references.

6. Keep D3D12 as the default backend, Vulkan as secondary.

   Do not duplicate all backend logic first. Define one PS5 GPU IR and one
   descriptor/resource model, then add D3D12 and Vulkan emitters. DXC and
   RenderDoc become mandatory once frames are visible.

7. Reduce link/probe cost before adding hundreds of stubs.

   Add `sccache`, Clang/LLD MinGW mode, response files, and a stable import
   registry object file that does not relink the entire runner for every small
   HLE change. Add Windows Job Object cleanup to every probe command.

## License handling

- GPLv2 sources (`SharpEmu`, `shadPS4`, `KytyPS5`) can be used only if the
  resulting distribution follows the same GPL obligations.
- GPLv3 sources (`ps5-payload-dev/sdk`, `SharpProspero`) should be treated as
  reference material unless the whole combined project is intentionally moved
  to GPLv3-compatible terms.
- No-license sources (`ida_ps5_elf_plugin`, as found locally) are reference
  only until licensing is clarified.
- MIT/Apache/permissive sources (`N64Recomp`, `ps3recomp`, `SPIRV-Cross`,
  `RenderDoc`, `QBDI`, `Remill`, etc.) are safer for direct reuse, subject to
  preserving notices.
